
# Campus Surveillance — Real‑time Face Recognition, Uniform Compliance, and Hazard Detection

An end‑to‑end, camera‑based surveillance system for campuses that:

- **Recognizes students** in real time from registered photos.
- **Checks uniform compliance** using color analysis on person detections.
- **Detects hazardous items** (e.g., knife, gun, fire/smoke) using YOLOv8.
- **Notifies admins** via SMS (Twilio) and email with cooldowns to prevent spam.
- **Streams a live dashboard** (Flask) with a camera feed and real‑time alerts.


## Key Features

- **Face recognition**: Encodes faces from the `students/` folder and matches live webcam faces.
- **Uniform detection**: Uses YOLOv8 person detection plus HSV blue‑color ratio to determine uniform usage.
- **Hazard detection**: YOLOv8 model with label filters and temporal persistence to reduce false positives.
- **Smart notifications**: SMS via Twilio and email for uniform violations, with event‑type cooldowns.
- **Live dashboard**: Flask app serving a live video stream, recent alerts, and Server‑Sent Events for instant updates.
- **Logging**: Alerts appended to `data/logs/alerts.json` (rolling window of recent events).

## How It Works (High‑Level Flow)

1. **Enrollment**
   - Place student photos in `students/` named like `22102027.jpeg` (filename = roll number).
   - Run the encoder to create `models/face_encodings.pkl`.

2. **Realtime Pipeline** (`src/realtime/face_recognition_live.py`)
   - Capture frames from webcam.
   - Detect faces and compute encodings; match against known encodings.
   - If known person:
     - Run uniform check via `utils/yolo_uniform_detector.py`.
     - Log uniform status; if violation and outside 24‑hour cooldown for that student, send email.
   - If unknown person:
     - Save snapshot, log event, and send SMS (subject to cooldown).
   - Run hazard detection via `detectors/anomaly_detector.py`:
     - YOLOv8 predictions filtered by hazard keywords, minimum box area, and multi‑frame persistence.
     - On confirm, log event and send SMS (subject to cooldown, and per‑item key).
   - Push events to dashboard via an in‑process queue and SSE endpoint.

3. **Dashboard** (`src/dashboard/app.py`)
   - `/` (login required): Live video stream + recent alerts.
   - `/video_feed`: MJPEG stream from the camera.
   - `/live_alerts`: SSE for instant alert updates.
   - `/alerts_data`: Recent alerts JSON.
   - Static route for anomaly snapshots under `data/anomalies/`.


## Prerequisites

- Python 3.9+ recommended.

- For SMS: Twilio account and credentials.

## Setup — Manual (Local)

1. **Install dependencies**
   - Create a virtual environment, then:
   ```bash
   pip install -r requirements.txt
   ```

2. **Add student photos**
   - Put `.jpg`/`.jpeg` images into `students/` with filename as the roll number.
   - Use clear, front‑facing images.

3. **Generate face encodings**
   ```bash
   python -m src.encoders.encode_faces
   ```
   - Outputs `src/models/face_encodings.pkl` (also mirrored at repo root `models/`).

4. **Environment variables** (for notifications)
   - Set these in your shell or a `.env` (if you load it) before running:
   ```bash
   export TWILIO_ACCOUNT_SID=...        # required for SMS
   export TWILIO_AUTH_TOKEN=...
   export TWILIO_PHONE_NUMBER=+1...
   export ADMIN_PHONE_NUMBERS="+1...,+1..."  # comma separated
   ```

5. **Run the realtime pipeline**
   - Option A: pipeline from terminal (shows OpenCV window; press `q` to exit)
   ```bash
   python -m src.realtime.face_recognition_live
   ```
   - Option B: run the dashboard (serves live feed and alerts)
   ```bash
   python -m src.dashboard.app
   ```
   - Visit http://localhost:5000 and log in with:
     - Username: `admin`
     - Password: `admin123`


## Setup — Docker (Optional)

The compose file defines two services:

- **backend**: mounts `src/` and `data/`, exposes camera device, runs Flask backend.
- **frontend**: serves the dashboard UI.

Run:
```bash
docker compose up --build
```

Notes:

- Camera passthrough uses `/dev/video0` and `privileged: true`. Adjust for your host if needed.
- Ports:
  - Dashboard on `5000` (frontend).
  - Backend service on `5001` mapped to container `5000`.


## Configuration Details

- **YOLO weights**: `yolov8n.pt` is used for uniform/person; `yolov8m.pt` for hazards. Both are included.
- **Uniform logic**: Detect `person` via YOLO, crop, convert to HSV, compute blue ratio; threshold = 0.05.
- **Hazard logic**: Filter by keywords `{knife, gun, fire, smoke, ...}`; min box area ratio = 1%; require N=3 consecutive frames.
- **Cooldowns**:
  - Unknown face SMS: 5 minutes between similar events.
  - Dangerous item SMS: 5 minutes per item type.
  - Uniform violation email: 24 hours per student.
- **Data dirs**: snapshots under `data/anomalies/` and `data/unknown_faces/`; logs in `data/logs/alerts.json`.


## Usage Tips

- Ensure good lighting and camera placement for stable recognition.
- Use clear, single‑face photos in `students/`.
- If you see too many false positives for hazards, raise `CONF_THRESHOLD` or `MIN_CONSECUTIVE_FRAMES` in `src/detectors/anomaly_detector.py`.
- If uniform color varies, adjust the HSV blue range in `src/utils/yolo_uniform_detector.py`.

## Troubleshooting

- Camera not found: check `/dev/video0` access and that no other process is using the webcam.
- Twilio errors: verify all `TWILIO_*` variables and reachable phone numbers.
- Face encodings empty: ensure faces are clearly visible in `students/` photos.
- High CPU/GPU: switch to `yolov8n.pt` for hazards or reduce frame rate.
